# 공통 지침 적용 범위

아래는 첨부 사용자 공통 작업 지침의 공통 부분(UWGL-01–11)을 발췌한 것이다. 원본 파일은 변경하지 않았다. 원본 UWGL-12는 별도 프로젝트의 운영에 관한 다른 업무의 구체 지시이므로 DarkHarness에 이식하지 않는다. 이것은 그 다른 업무에서의 지시를 폐기하는 결정이 아니다. 현재 대화의 최신 사용자 결정과 실제 강제 제약이 우선한다.

공통 작업 지침 (UWG-Lite)

전제: 공통설계철학을 따른다.
성격: 이 문서는 철학을 실제 작업에 적용하기 위한 압축 작업 지침이며 새로운 제품·업무 정책을 만들지 않는다.

1. UWGL-01  현재 유효한 사용자 결정과 실제 적용되는 제약을 먼저 확인하고, 미승인 문서·AI 산출물·baseline을 권위로 승격하지 않는다. 작업을 정당화하거나 제한하는 상위 근거에 의존한다면 그 식별자·유효 버전과 필요한 내용을 실제로 확인할 수 있어야 한다. 파일명이나 어딘가 존재한다는 설명만으로는 충족되지 않는다. 이용할 수 없는 자료의 내용을 추정하지 않되, 미첨부 자체를 중단이나 재승인 사유로 삼지 않는다. 판단에 실제로 필요하면 그 쟁점에 한해 자료를 확인하고, 영향받지 않는 작업은 계속한다.
2. UWGL-02  의도된 상태와 현재 상태를 구분하고, 차이를 근거 없이 결함이나 요구사항으로 확정하지 않는다.
3. UWGL-03  모호함을 새 정책으로 채우지 않으며, 예시·권장값·기본값·강제조건을 구분한다.
4. UWGL-04  실행 수단·모델·도구의 선택을 의미·정책·권한과 불필요하게 결합하지 않고, 결과에 영향을 주는 입력·설정·기준 상태만 일관되게 고정한다.
5. UWGL-05  계획·작성·검증·실행·통합 상태와 PASS / FAILED / UNKNOWN, PARTIAL / COMPLETE, 권한 상태를 혼동하지 않고, 주장 범위는 실제 증거를 넘지 않는다. 부분 실행자의 실패·BLOCKED를 전체 작업의 실패·차단으로 자동 전파하지 않고, 의존관계와 승인 범위 안의 대체·복구 가능성으로 영향 범위를 판정한다.
6. UWGL-06  finding은 후보일 뿐이며 원천·실제 상태·증거로 다시 판정한다. 순환논증이나 같은 계보의 산출물을 독립 검증으로 세지 않는다.
7. UWGL-07  기계적으로 검증 가능한 것은 적절한 검증 장치로 옮기되, 검증을 이유로 새 정책·제약·승인 단계를 만들지 않는다. 정적 검토로 닫히지 않는 불확실성은 실제 수행·관찰로 넘긴다.
8. UWGL-08  검증 엄격성과 승인 단위를 분리하고, 중단·진행 불가의 원인을 복구 가능한 기계적 결함 / 예상된 내부 장벽 / 실질적 안전 차단 / 진짜 사용자 결정 필요로 구분해 처리한다.
9. UWGL-09  재승인은 기존 승인 범위로 정당화되지 않는 의미·정책·권한·위험·계보·외부효과의 선택이나 확대가 필요할 때 요구하며, 같은 승인 범위의 복구·재시도·위임·검증 갱신에는 반복 승인 요구를 만들지 않는다. 다만 기준 원천의 정체성과 내용을 확인하지 않은 채 해시·참조·증빙을 다시 맞추지 않으며, 외부 변경의 성공 여부가 UNKNOWN이면 중복 효과 가능성을 확인하기 전 재실행하지 않는다.
10. UWGL-10  복합·장기 작업은 필요한 원천·권한·진행·증거·남은 위험·다음 행동을 재개 가능하게 남기고, 모든 절차와 기록은 작업의 위험·복잡도·가역성에 비례시킨다.
11. UWGL-11  실행 권한이나 제약을 운반하는 지시·증빙은 의존 행동을 시작하기 전에 완성·검증되어 있어야 한다. 필요한 권한·안전 근거가 확인되지 않으면 그 행동을 허용하지 않는다.
